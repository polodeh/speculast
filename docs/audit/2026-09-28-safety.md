# Аудит Speculast и исправление опасных операций

Дата: 2026-09-28. Исходный коммит `main`: `606a33f285083ce93266400ca4efd01e18a274d3`.
Работа велась на локальной ветке `feature/safety-hardening`. До правок исходный коммит
сохранён на GitHub в ветке `archive/pre-v2` и аннотированном теге
`archive/pre-v2-2026-09-28-606a33f`; обе ссылки проверены через `git ls-remote`.

## Что реализовано

| Область | Подтверждение в коде | Ограничение |
| --- | --- | --- |
| CLI | `main.py`: разбор аргументов и `execute_pipeline` | По умолчанию включает тесты, реальные БД и генерацию HTML; запуск на чужом проекте требует осторожности. |
| AST и интроспекция | `AnalyzerEngine` читает `.py`, применяет `ast.parse` и посетители импортов, определений и вызовов. Сгенерированный тест применяет `inspect` во время запуска. | Статический анализ не выполняет произвольные динамические импорты и не доказывает семантику кода. Ошибочный синтаксис фиксируется предупреждением. |
| Семантическая модель | Pydantic-схемы в `engine/core/models.py`, контекст функций и эвристики внешних вызовов | Русские подписи в части `engine/analyzer/engine.py` выглядят повреждёнными кодировкой; это вне текущего исправления. |
| Зависимости и граф | `CallsVisitor`, `DependencyRegistry`, `_build_graph_payload` в визуализаторе | Граф строится из обнаруженных вызовов и импортов, а не из подтверждённого runtime-трейса. |
| Генерация pytest | Jinja2-шаблоны, `GeneratorEngine.generate`, план тестов | Тесты эвристические; имитации HTTP/БД не заменяют проверку реального поведения. |
| Инфраструктура | Импорты `asyncpg`/`sqlalchemy`/`psycopg2` и `redis` вызывают планирование PostgreSQL/Redis | Импорт SQLAlchemy сам по себе не доказывает, что проекту нужна PostgreSQL. Docker не запускался в этом аудите. |
| Тесты, покрытие, отчёты | `pytest-json-report`, `pytest-cov`, JSON в каталоге запуска, HTML через `VisualReportRenderer` | Интеграционный тест образца использует фиксированное имя контейнера и вызывает `docker rm -f`; поэтому здесь он не запускался. |

## Подтверждённые дефекты исходного коммита

1. `GeneratorEngine.generate` безусловно записывал заданный `test_*.py`,
   `tests/conftest.py`, `tests/pyproject.toml`, а `_cleanup_legacy_generated_suite`
   удалял `tests/unit/test_logic.py` и `tests/integration/test_service.py` без проверки
   происхождения. Изолированный тест показал замену пользовательского теста.
2. `cleanup_temp_artifacts` рекурсивно удалял элементы корня, если имя начиналось
   с точки или содержало `tmp`, включая пользовательские файлы и каталоги.
   Изолированный тест потерял `.custom-data/important.txt`.
   Дополнительно `migrate_legacy_report_artifacts` перемещал неизвестные файлы
   `report*`, `cleanup_old_reports` удалял их по имени и возрасту, а
   `VisualReportRenderer.generate` перезаписывал явно указанный HTML-путь.
3. `InfraManager.create_compose_file` записывал `docker-compose.yaml` в корень
   проекта через `write_text`, а Docker-команды использовали Compose по умолчанию.
   Изолированный тест показал замену пользовательского файла.

Три регрессии до исправления: `3 failed` (`evidence/regression-red.txt`).

## Принятые решения

- CLI создаёт отдельный каталог `.speculast/runs/<uuid>/` для каждого запуска.
  Генератор отказывается перезаписывать любой существующий тест или конфигурацию;
  ранее созданные `tests/unit` и `tests/integration` больше не удаляются.
- Эвристическая очистка корня отключена. Неизвестные старые `report*` не
  перемещаются. Очистка старых HTML-отчётов допускается только для файлов с
  маркером владения и совпадающим SHA-256 содержимого. Цена безопасного решения:
  старые и временные файлы, владение которыми нельзя доказать, остаются на диске.
- Compose записывается в каталог конкретного запуска с эксклюзивным созданием.
  Команды Docker получают явные `-f` и уникальное `-p`, а `down` больше не
  использует `--remove-orphans`. Тесты фиксируют команду без обращения к Docker.
- JSON pytest, JSON coverage и файл `.coverage` находятся в каталоге запуска.
  Pytest не пишет свой кеш в корень анализируемого проекта.
- HTML-рендерер также создаёт файл эксклюзивно; отдельный тест до исправления
  воспроизвёл перезапись (`evidence/report-renderer-red.txt`).

Публичные аргументы `GeneratorEngine.generate` и `InfraManager.create_compose_file`
сохранены. Повторная генерация в **явно указанный существующий путь** теперь
вызывает `FileExistsError`; результат надо записывать в новый путь.
`cleanup_temp_artifacts` теперь возвращает пустой набор, пока нет надёжного
реестра владения временными файлами. Старые отчёты без маркера больше не
мигрируют и не очищаются автоматически.

## Проверки и границы результата

- До исправления: 43 теста без Docker прошли (`evidence/baseline-pytest.txt`).
- После исправления: 50 тестов прошли в наборе `tests/unit` и
  `tests/integration/test_windows_compatibility.py` (`evidence/postchange-pytest.txt`).
- Изолированный CLI-запуск с существующими `tests/conftest.py`, пользовательским
  `docker-compose.yaml` и скрытым каталогом завершился с кодом 0, сохранил их
  содержимое и создал отдельный набор тестов. Второй запуск с импортом `asyncpg`
  создал отдельный Compose-файл; запуск pytest дал 1/1 успешный тест и JSON-покрытие
  в каталоге запуска (`evidence/smoke-cli-tests.txt`).
- `ruff check .` обнаружил 214 замечаний по дереву, включая неизменённые файлы.
  Массовое форматирование не входит в это исправление.
- Полный `pytest` и реальные Docker-команды не запускались: фикстура
  `tests/conftest.py` может выполнить `docker rm -f speculast-test-postgres`.
  Поведение с реальным Docker остаётся непроверенным.
- Фиксированные порты сгенерированного Compose (`55432`, `6379`) могут быть заняты.
- В `pyproject.toml` установка `.[dev]` не установила `greenlet`, нужный
  `sqlalchemy.ext.asyncio`; для тестов он был добавлен только в отдельное venv.

## Независимое ревью

Два независимых read-only прохода рассмотрели diff к исходному `main` по
стандартам и по требованиям. Обнаруженные замечания устранены: некорректный
маркер отчёта теперь игнорируется, HTML создаётся эксклюзивно, регрессия
проверяет `FileExistsError`, повторный прямой вызов генератора Compose создаёт
новый путь, а README обновлён. По документированным стандартам нового строгого
нарушения не найдено. Риск занятых портов Compose остаётся непроверенным без Docker.

## Воспроизведение безопасных проверок

На локальном Python 3.12 с установленными зависимостями и `greenlet`:

```text
python -m pytest -q tests/unit tests/integration/test_windows_compatibility.py -p no:cacheprovider
python -m pytest -q tests/unit/test_safety_regressions.py -p no:cacheprovider
python -m ruff check .
```

Для проверки CLI использовать отдельный временный проект и флаги
`--no-real-db --no-viz`; тестовые данные аудита находились вне репозитория.
